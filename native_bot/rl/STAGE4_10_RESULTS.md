## 资源实测

CPU 与 GPU 每 0.2 秒采样，对局期间各得到 38 个样本。nvidia-smi 的 GPU 利用率本身
有驱动采样窗口，因此这些不是 38 个独立统计样本；该短测不能代替长时间资源压测。

| 资源 | 对局期间实测 |
|---|---|
| GPU 利用率 | 平均 11.13%，峰值 12% |
| 显存占用 | 503 MiB，占 49,140 MiB 的约 1.02% |
| 任务 CPU | 约 1.004 个逻辑核，折合整机约 0.90% |
| 整机 CPU（含后台） | 平均 1.23%，峰值 3.3% |
| 进程内存 RSS | 约 1.01 GiB |
| 整机内存使用率 | 平均 5.30%，峰值 5.4% |

内存使用率采用 psutil 的 used/available 口径，不将可回收文件缓存视为不可用内存。
显存容量占用与 GPU 利用率分别报告，不混为一个指标。

时间分解：观察适配约 2.17 秒，推理端到端调用约 4.88 秒，动作解析和环境推进约
0.43 秒，其余为初始化、循环、计时和输出。推理端到端时间含数据复制、合法掩码、
同步及结果回传，不等于 GPU 计算时间。瓶颈更接近小批次调用和串行调度，而非显存不足。

## 1,000 场串行估算

按本次均值：`7.5429 × (1000 / 10) = 754.29 秒`，即 **约 12.6 分钟**。
实际排期建议预留 **15–20 分钟**，作为对局长短、机器负载和记录开销的余量。
这不是统计置信区间；只有 10 场样本，无法保证未来不同策略/种子的平均时长相同。
这里的 1,000 场指 1,000 个实际半庄；若运行 1,000 个种子再各轮换四个座位，是 4,000 场。

## 阶段 5 并发预算（未实测）

方案前提：每个 CPU worker 承载 4 桌；所有 worker 不初始化 CUDA；单个 GPU 服务集中
批量推理，沿用当前模型与推理流程。它不是同时启动多个各自占用 GPU 的独立脚本。

测得非推理部分的 CPU 时间约为每决策 0.410 毫秒。以
`min(worker数 / 0.000410, 对应batch的推理吞吐量)` 为容量上限，再假设最终系统只达到
该上限的 25%–50%，为 IPC、排队、凑批和多核损耗留余量。这个折扣是**未验证的规划
假设**，不是测出来的并发效率。启动余量分别取 10–20、15–30、20–40 秒。

| CPU workers / 桌数 | 1,000 场预算（含启动余量） | 整机 CPU 预算 | 任务内存预算 | 含当前后台的整机内存 |
|---|---|---|---|---|
| 4 / 16 | 约 2.5–5 分钟 | 约 1–5% | 约 2.3–4.0 GiB | 约 7–8% |
| 8 / 32 | 约 1.5–3 分钟 | 约 2–9% | 约 3.3–6.1 GiB | 约 8–10% |
| 16 / 64 | 约 1–2 分钟 | 约 4–16% | 约 5.4–10.1 GiB | 约 9–13% |

CPU 百分比使用 112 逻辑处理器口径；区间由 worker 部分忙碌到全部忙碌及服务/IPC
余量构成。内存范围来自独立 worker 的 USS/RSS 和 0.25–1 GiB 队列余量，实际共享情况
及长期分配器行为仍需测量。

集中 GPU 服务的显存预计约 **0.5–1 GiB（约 1%–2%）**。在上述吞吐假设下，若批次始终
凑满，将批推理压力段 GPU 利用率按调用频率缩放，得到的忙碌时间代理分别约为
2%–4%、4%–8%、2.5%–5%。这些代理不是已验证的 GPU 利用率预测；小批次和排队策略
会改变结果，当前推理实现的连续 batch 16/64 压力段上限实测约 20%/23%。
因此工程预算可粗略按 **2%–25% GPU 利用率**考虑，阶段 5 必须实测确认，不能承诺满载。
若之后改用异步 GPU 流水线、CUDA Graph 或其他推理优化，该范围也需重新测定。

上述估算仅针对冻结策略对战/采样，**不包含 PPO 反向传播、优化器、rollout 缓冲区、
定期评估和检查点开销**。建议阶段 5 从 4 workers / 16 桌开始，再实测扩至 8 和 16 workers。
